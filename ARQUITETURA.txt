1. VISAO GERAL
--------------
Um projeto Firebase (bluezone-d2757, conta contato@abluezone.com.br) concentra tudo:
site, banco, login, backend e, depois, os apps Android e iOS. Nada precisa ser
refeito quando os apps chegarem: eles usam as mesmas Functions, o mesmo banco e as
mesmas regras.

Regra de ouro: o navegador e os apps NUNCA escrevem dados sensiveis direto no banco.
Toda escrita passa pelo backend (Cloud Functions), que valida, limita e registra.

3. ETAPA 1 - BANCO E BACKEND (proxima)
--------------------------------------
Objetivo: leads e "registro de eventos" (timeline do que acontece com cada lead/aluno)
no Firestore, com a planilha mantida como espelho para a equipe.

Pecas:
- Cloud Firestore (banco)
- Cloud Functions (backend; exige plano Blaze - pago por uso, custo ~zero no volume atual)
- App Check (so o nosso site/app consegue chamar o backend)
- Security Rules (nega tudo por padrao)

Colecoes (esboco):
  leads/{leadId}          nome, email, telefone, origem, criadoEm, atualizadoEm, status
  events/{eventId}        leadId ou uid, tipo (contato | email | ligacao | reuniao |
                          proposta | compra | inscricao ...), origem, detalhes, data, autor
  users/{uid}             perfil de quem tem login (criado no primeiro login)
  courses/{courseId}      cursos (Blueprint, futuros)
  enrollments/{uid_curso} acesso liberado a um curso (por compra ou manual)
  products/{productId}    catalogo (Blueprint, IA automacao, IA conteudo, BlueCast, plataforma)

Fluxo do formulario:
  site -> Function submitLead (App Check + validacao + limite) -> leads + events
       -> e-mail para contato@ -> espelho na planilha (opcional, via API do Sheets)
